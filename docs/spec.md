# 每日跑步签到打卡 App 规格说明

## Problem Statement

用户希望在手机上使用一个 Android App，每天记录跑步签到，并通过账号在云端同步数据。核心诉求是：打开 App 后能快速开始跑步，使用 GPS 记录轨迹和距离，结束后自动生成打卡记录，并能查看历史、连续打卡天数和跑步统计。

## Solution

构建一个前后端分离项目：

- 客户端：Expo + React Native，面向 Android，支持登录注册、GPS 实时轨迹、地图路线、跑步打卡、历史记录和个人统计。
- 服务端：Node.js + Express，提供 JWT 鉴权、用户管理、跑步记录、轨迹点和统计接口。
- 数据存储：开发环境使用本地 JSON 文件持久化，便于直接运行；生产环境可平滑迁移到 PostgreSQL/MySQL。

## User Stories

1. 作为用户，我希望注册账号，以便我的跑步数据可以云端保存。
2. 作为用户，我希望使用用户名和密码登录，以便在不同设备访问我的数据。
3. 作为用户，我希望退出登录，以便保护账号安全。
4. 作为用户，我希望在首页看到今天是否已打卡，以便快速判断是否需要跑步。
5. 作为用户，我希望看到连续打卡天数，以便保持跑步习惯。
6. 作为用户，我希望看到本月累计跑步距离和次数，以便了解运动进展。
7. 作为用户，我希望一键开始跑步，以便快速进入记录状态。
8. 作为用户，我希望 App 请求 GPS 权限，以便记录跑步路线。
9. 作为用户，我希望在跑步时实时看到当前距离、时长和配速，以便控制运动强度。
10. 作为用户，我希望在地图上看到实时轨迹，以便确认路线正在被记录。
11. 作为用户，我希望暂停和继续跑步，以便中途短暂休息。
12. 作为用户，我希望结束跑步并保存打卡，以便生成一条完整记录。
13. 作为用户，我希望为一次跑步添加备注，以便记录天气、感受或训练内容。
14. 作为用户，我希望查看历史跑步列表，以便回顾过去的打卡。
15. 作为用户，我希望查看单次跑步详情，以便看到路线、距离、时长、配速和时间。
16. 作为用户，我希望按月份查看统计，以便分析长期跑步情况。
17. 作为用户，我希望数据在登录后自动同步，以便换手机后不丢失记录。
18. 作为用户，我希望网络失败时看到明确提示，以便知道打卡是否保存成功。
19. 作为用户，我希望 App 在 Android 上可安装运行，以便日常使用。
20. 作为用户，我希望密码不会明文存储，以便账号更安全。

## Implementation Decisions

### 总体架构

- 仓库采用 `mobile/` 与 `server/` 双目录结构。
- 客户端通过 HTTPS/HTTP 调用服务端 REST API。
- 登录成功后客户端保存 JWT，后续请求携带 `Authorization: Bearer <token>`。
- 跑步轨迹在客户端采集，结束跑步时一次性提交距离、时长和轨迹点数组。

### 服务端模块

- 认证模块：注册、登录、返回 JWT。
- 用户模块：获取当前用户信息。
- 跑步模块：创建跑步记录、查询列表、查询详情。
- 统计模块：连续打卡天数、月度距离、月度次数、总距离。
- 存储模块：封装 JSON 文件读写，后续可替换为数据库实现。

### 数据模型

用户：

- 唯一 ID
- 用户名
- 邮箱（可选）
- 密码哈希
- 创建时间

跑步记录：

- 唯一 ID
- 用户 ID
- 开始时间
- 结束时间
- 距离（米）
- 时长（秒）
- 平均配速（秒/公里）
- 消耗卡路里（可选，客户端可估算）
- 备注
- 创建时间

轨迹点：

- 唯一 ID
- 跑步记录 ID
- 纬度
- 经度
- 精度
- 时间戳
- 序号

### API 契约

- `POST /api/auth/register`：注册。
- `POST /api/auth/login`：登录。
- `GET /api/me`：获取当前用户。
- `POST /api/runs`：保存一次跑步打卡和轨迹。
- `GET /api/runs`：获取当前用户跑步列表，支持月份筛选。
- `GET /api/runs/:id`：获取单次跑步详情和轨迹。
- `GET /api/stats/summary`：获取今日、连续打卡、本月和累计统计。

### 客户端模块

- 认证页：注册、登录、错误提示。
- 首页：今日打卡状态、连续天数、本月统计、开始跑步入口。
- 跑步记录页：GPS 权限申请、实时位置、轨迹地图、距离、时长、配速、暂停/继续/结束。
- 历史页：跑步记录列表。
- 详情页：单次跑步地图和指标。
- 个人页：用户信息、累计统计、退出登录。

### GPS 与地图

- 使用 `expo-location` 请求定位权限并监听位置更新。
- 使用 `react-native-maps` 展示地图和轨迹折线。
- 距离使用 Haversine 公式基于轨迹点累计计算。
- 第一版以前台记录为主，不实现后台长期追踪。

### 安全与稳定性

- 密码使用 bcrypt 哈希存储。
- JWT 设置过期时间。
- 服务端对输入进行基础校验。
- 客户端对未登录、定位权限拒绝、网络失败进行提示。

## Testing Decisions

- 服务端通过启动后调用注册、登录、创建跑步、查询统计接口进行冒烟测试。
- 重点测试外部行为：认证是否成功、跑步是否保存、统计是否随新记录变化。
- 客户端通过工程结构、依赖配置、页面导航和关键工具函数检查保证可运行性。
- 距离计算函数应使用已知经纬度样例进行单元级验证。

## Out of Scope

- iOS 发布和 App Store 配置。
- 社交关注、点赞、评论。
- 付费会员、广告和数据商业化。
- 可穿戴设备同步。
- 复杂训练计划和 AI 教练。
- 后台无限轨迹追踪和省电优化。
- 生产级数据库部署、CI/CD 和云服务器配置。

## Further Notes

- 本项目优先保证 Android 可运行、可打包和可扩展。
- 服务端默认使用 JSON 文件存储，适合演示和个人使用；多人高并发场景应迁移到关系型数据库。
- 打包 Android APK 推荐使用 EAS Build 或本地 Android Studio Gradle 构建。
